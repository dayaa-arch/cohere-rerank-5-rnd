日本語の業務文書（国税庁タックスアンサーの源泉所得税）で作った40問で、Cohere Rerank 5 と Rerank 4 Pro、日本語OSSの ruri-v3-reranker を比べました。結論は次の3つです。

- 精度は、リランカーを入れると大きく上がりますが、Rerank 4 Pro から 5 Pro／5 Fast に替えても差は見えませんでした（40問では誤差の範囲）
- 1問あたりの費用は、5 Pro が 4 Pro の約14分の1、5 Fast が約23分の1でした
- 新機能の Context Focus は、400字以内に切ったチャンクではトークンを1割前後しか減らしませんでした。ページ全文を渡すと6割以上減りました。較正スコアは、公式のしきい値のままで「答えがない質問」の候補をすべて弾けました

乗り換えの理由になるのは、精度より、費用と較正スコアだと筆者は考えます。

![比較表](/images/rerank5/fig_x_card.png)

## 何を確かめたか

Cohere は2026年10月21日に Rerank 5 を発表しました。公式ブログでは、日本語のスコアは 5 Pro が89.4、4 Pro が89.3、5 Fast が86.8 で、5 Pro と 4 Pro はほぼ同じです（いずれも Cohere の自社評価）。精度がほぼ同じなら、乗り換える理由はほかにあるはずです。公式ブログが挙げている新しい点は、次の2つです。

- **Context Focus**：文書の中で質問に関係する箇所（スパン）を、スコアつきで返す。関係のない部分を削って、LLM に渡すトークンを減らせる
- **較正スコア**：スコアを「役に立つ確率」として読めるように調整してある。「役に立つ可能性が高い」境目は、Pro が0.50、Fast が0.45

そこで、次の3つを日本語の業務文書で確かめました。

1. 4 Pro から 5 Pro／5 Fast に替えると、精度は変わるか。リランカーなしと比べて、どれだけ上がるか
2. Context Focus で、LLM に渡すトークンをどれだけ減らせるか。答えの箇所を落とさないか
3. 公式のしきい値だけで、関連のある候補とない候補をどこまで分けられるか

## 検証の設計

### コーパスと質問

コーパスは、国税庁ホームページの「タックスアンサー」のうち、源泉所得税の65ページです。公共データ利用規約（第1.0版）に従って利用しています。社内FAQに近い、条件と例外の多い業務文書です。

ページを見出しの節ごとに、400字以内のチャンクに分けました（345チャンク、中央値280字）。チャンクの先頭には「ページ名｜見出し」を付けています。

質問は40問で、内訳は次のとおりです。

| 種類 | 問数 | 例 |
| --- | --- | --- |
| 素直な事実検索 | 12 | 司法書士に報酬を支払うときの源泉徴収税額はどう計算しますか |
| 言い換え | 12 | 社員のランチ代を会社が一部負担… → 本文は「食事を支給したとき」 |
| 複数箇所にまたがる | 8 | 納期の特例を受けている会社の、弁護士報酬と外交員報酬の納付期限 |
| 答えがコーパスにない | 8 | 住民税の特別徴収、給与支払報告書の提出期限など |

質問と正解チャンクの案は Claude Code が作り、筆者が確かめました。言い換えの問題は、質問文と正解チャンクで共通する文字の並びの割合が平均0.26で、事実検索（0.79）より大きく下がっていることを確かめました。

### 比べた条件

1段目の検索は `cl-nagoya/ruri-v3-310m` で上位20件を取り、全条件で同じ20件を同じ順に渡しました。

| 条件 | モデル |
| --- | --- |
| A | リランカーなし（1段目の順のまま） |
| B | `rerank-v4.0-pro` |
| C | `rerank-v5.0-pro` |
| D | `rerank-v5.0-fast` |
| C2・D2 | C・D に Context Focus（threshold 0.1 と 0.4） |
| E | `cl-nagoya/ruri-v3-reranker-310m`（CPU、ローカル実行） |

各条件で40問を3回ずつ呼び、精度は1回目の順位で、遅延は3回の中央値で計算しました。API の生の応答はすべて保存し、指標は保存した応答から計算しています。

精度の指標は、1段目の上位20件に正解が入った31問で計算しました。1問（ソフトウェアのライセンス料を聞いた言い換えの問題）は、1段目で正解を取りこぼしたので外しています。

## 結果1：精度はリランカーで大きく上がるが、モデル間の差は誤差の範囲

| 条件 | 1位が正解 | MRR | nDCG@10 |
| --- | --- | --- | --- |
| リランカーなし | 65％ | 0.801 | 0.863 |
| Rerank 4 Pro | 87％ | 0.930 | 0.940 |
| Rerank 5 Pro | 94％ | 0.962 | 0.946 |
| Rerank 5 Fast | 90％ | 0.946 | 0.932 |
| ruri-v3-reranker（CPU） | 90％ | 0.941 | 0.929 |

![精度](/images/rerank5/fig_accuracy.png)

リランカーを入れると、1位が正解の問題は31問中20問から27〜29問に増えました。どのリランカーでも、リランカーなしとの差の95％信頼区間は0をまたぎません。

一方、5 Pro と 4 Pro の差は、MRR で +0.032（95％信頼区間 −0.03〜+0.10）でした。5 Pro が上回ったのは3問、下回ったのは1問で、残りの27問は同じ順位でした。この問題数では、差を偶然と区別できません。公式発表の「ほぼ同じ」と食い違わない結果です。

無料の ruri-v3-reranker も、5 Fast とほぼ同じ精度でした。ただし、CPU（4スレッド）では1問あたり約8秒かかりました。

なお、上位5件に正解が入る割合（Recall@5）は、リランカーなしでも0.97ありました。1段目の検索が強く、正解はほぼ5件以内に入っています。リランカーの差は「正解を1位に上げられるか」に出るので、比較には MRR と nDCG@10、1位が正解の割合を使いました。

## 結果2：Context Focus は、短いチャンクではほとんど削れない

Context Focus を有効にすると、各文書に、質問に関係する箇所（スパン）がスコアつきで返ります。上位5件をスパンだけに削ったとき、トークンがどれだけ減るかを測りました。トークン数は ruri-v3 のトークナイザーで数えています。

| 渡した単位 | モデル（threshold 0.4） | 上位5件の全文 | 削った本文 | 削減率 | 根拠の文が残った割合 |
| --- | --- | --- | --- | --- | --- |
| チャンク（400字以内） | 5 Pro | 717 | 637 | 11％ | 98％ |
| チャンク（400字以内） | 5 Fast | 706 | 635 | 10％ | 96％ |
| ページ全文（中央値980字） | 5 Pro | 3,450 | 1,327 | 62％ | 100％ |
| ページ全文（中央値980字） | 5 Fast | 3,471 | 1,176 | 66％ | 98％ |

「根拠の文」は、各問で答えを述べている文字列（52件）を本文から抜き出しておき、削ったあとの上位5件に丸ごと残ったかで数えました。

チャンク単位では、threshold 0.1 では1.5％、0.4 でも1割前後しか減りませんでした。スパンは文の区切りで返り、関連の薄い文にも0.1を超えるスコアが付きます。400字以内のチャンクは、どの文も同じ話題を扱っているので、削れるのは見出しの行や前置きの1文くらいでした。

そこで、同じ候補を元のページにまとめ、ページ全文を渡して測り直しました。1ページには、質問と関係のない節（ほかの場合の説明や具体例）が含まれているので、6割以上が削れました。答えの根拠は、ほぼすべて残りました。

ただし、削ったあとのページ5件（約1,200〜1,300トークン）は、削ったチャンク5件（約640トークン）の約2倍あります。LLM に渡すトークンを最も少なくしたいなら、細かく切ったチャンクのほうが少なく済みます。一方、根拠が残った割合はページ単位のほうが高くなりました。チャンク単位では、答えのチャンクが上位5件から漏れることがあるのに対し、ページ単位では同じページの別の節が候補に入れば、答えの節もいっしょに届くためです。

Context Focus は、「長めの文書をそのまま渡し、必要な部分だけ LLM に送る」構成で効く機能です。課金トークンは Context Focus の有無で変わらず、遅延の差も20ミリ秒以内でした。

## 結果3：公式しきい値のままで、答えのない質問を弾けた

公式しきい値（Pro 0.50、Fast 0.45）以上を「関連あり」とみなしました。

| モデル | 答えのない8問で全候補がしきい値未満 | 答えのある31問で1件以上がしきい値以上 |
| --- | --- | --- |
| 5 Pro | 8問（100％） | 30問 |
| 5 Fast | 8問（100％） | 31問 |

5 Pro で取りこぼした1問（特許の権利の買い取りを聞いた言い換えの問題）は、正解を1位にしていましたが、スコアが0.455でした。しきい値で候補を絞ると、この問題の答えは LLM に渡りません。

1位のスコアの分布を比べると、モデルの違いがよくわかります。

| モデル | 答えのない8問の1位の最大 | 答えのある31問の1位の最小 |
| --- | --- | --- |
| 4 Pro | 0.812 | 0.890 |
| 5 Pro | 0.125 | 0.455 |
| 5 Fast | 0.141 | 0.455 |
| ruri-v3-reranker | 0.174 | 0.652 |

4 Pro も、0.85前後に線を引けば分けられます。ただ、答えがなくても0.5〜0.8を出すので、その線は実際のデータを見ないと決められません。5 Pro・5 Fast は、答えのない質問のスコアが0.15以下に集まり、公式しきい値の手前に広い余白がありました。

ruri-v3-reranker もスコアが0と1に寄っていて、このデータでは0.5で分けられます。ただし ruri には公式のしきい値がないので、0.5はこのデータを見てから決めた値になります。分けられること自体は Rerank 5 だけの特長ではありません。Rerank 5 の利点は、しきい値を事前に決められることです。

## 速さと費用

| モデル | 遅延 p50 | 遅延 p95 | 1問あたり費用 |
| --- | --- | --- | --- |
| 4 Pro | 499 ms | 647 ms | 0.0025 ドル |
| 5 Pro | 434 ms | 486 ms | 0.00018 ドル |
| 5 Fast | 416 ms | 468 ms | 0.00011 ドル |
| ruri-v3-reranker（CPU） | 7,789 ms | 10,583 ms | — |

![精度と遅延・費用](/images/rerank5/fig_tradeoff.png)

遅延はネットワーク込みで、クラウドの実行環境から日本時間18時台に測りました。

費用は、API の応答に含まれる課金量に単価を掛けました。Rerank 5 はトークン単位（Pro 0.05ドル、Fast 0.02ドル／100万トークン、公式ブログの値）、4 Pro は検索単位（1回の呼び出しで1単位）の課金です。4 Pro の単価（1,000検索単位あたり2.50ドル）は第三者サイトの値で、Cohere の料金ページでは確かめられませんでした。

同じ候補20件でも、5 Pro の課金は平均3,608トークン、5 Fast は5,350トークンでした。トークンの数え方がモデルで違うようです。それでも、1問あたりの費用は Fast のほうが安くなりました。

今回の検証の API 費用は、本実行（1,080回）が0.40ドル、ページ単位の追加実験（80回）が0.026ドルでした。

## 差が出た問題

### 4 Pro が「別の賞金の規則」と取り違えた

「広告宣伝のための賞金を個人に支払う場合、いくら以下なら源泉徴収は不要ですか」という質問です。正解は「50万円以下なら不要」のチャンクですが、4 Pro は「懸賞応募作品の入選者への賞金は5万円以下なら不要」のチャンクを、同じスコア（0.960）で1位にしました。5 Pro・5 Fast・ruri は正解を1位にしました。どちらのチャンクにも「賞金」「以下」「源泉徴収をしなくてもよい」が出てくるので、「広告宣伝」と「懸賞応募」の違いを読み分けられるかが分かれ目になったと考えられます。取り違えると、答えの金額が10倍違います。

### 1段目で取りこぼした問題を、ページ単位なら拾えた

「海外の会社にソフトウェアのライセンス料を払うとき、何パーセントを天引きすればよいですか」という質問は、1段目の上位20件に正解のチャンク（著作権等の使用料：20.42％）が入りませんでした。チャンク単位では、どのリランカーでも救えません。ところが、同じページの別のチャンクは20件に入っていたので、ページ単位の候補にはそのページが含まれ、5 Pro・5 Fast とも1位にしました。ただし、スコアは5 Pro で0.135と低く、しきい値で絞ると「答えなし」として扱われます。

## 乗り換えの判断

筆者の見方をまとめます。

- **すでに Rerank 4 Pro を使っているなら、乗り換えてよい。** 精度は同等で、費用は大きく下がり、`model` を替えるだけで移行できます
- **「答えがありません」と返したいなら、Rerank 5 の較正スコアが役に立つ。** しきい値を自分のデータで調整する手間が減ります。ただし、しきい値ぎりぎりの正解を落とすことはあります
- **Context Focus は、文書の切り方しだい。** 細かく切ったチャンクに足しても、ほとんど削れません。長めの文書をそのまま渡す構成なら、トークンを6割以上減らせます
- **費用をかけられないなら、ruri-v3-reranker も候補になる。** 精度は 5 Fast と同等でした。ただし、GPU なしでは1問あたり数秒かかります

## 限界

- 問題数は40問（精度は31問）と少なく、モデル間の数ポイントの差は誤差に埋もれます
- 1段目の検索が強く、リランカーで上げられる余地が小さいデータでした。もっと弱い1段目なら、モデル間の差が広がるかもしれません
- コーパスは1種類（源泉所得税）です
- 評価データは Claude Code が作り、筆者が確かめました。作り手と確かめた人の判断が入っています（たとえば、ソフトウェアのライセンス料を著作権の使用料とみなした問題があります）
- 4 Pro の単価は公式に確かめられていません
- 遅延は1か所・1時間帯の測定です
- トークン数は ruri-v3 のトークナイザーで数えました。LLM ごとにトークン数は変わります

## 再現方法

コード、評価データ、生の応答はすべて [GitHub](https://github.com/dayaa-arch/cohere-rerank-5-rnd) で公開しています。保存済みの応答から比較表とグラフを作り直すだけなら、API キーは要りません。

```bash
uv sync
uv run python -m rerank_ja_bench.pipeline --run results/2026-10-25
```
